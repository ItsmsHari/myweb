## PART 1: PERFORMANCE TESTING

### 1.1 Overview
Performance testing measures how a system performs under load, including response 
time, throughput, resource utilization, and stability.

### 1.2 Types of Performance Testing

1. LOAD TESTING
   - Objective: Measure system behavior under expected loads
   - Scenarios:
     * Normal load: 50 concurrent users for 10 minutes
     * Peak load: 200 concurrent users for 15 minutes
   - Metrics: Response time, throughput, CPU, memory usage
   - Tools: JMeter, LoadRunner, Locust

2. STRESS TESTING
   - Objective: Find breaking point of the system
   - Scenarios:
     * Gradually increase users from 100 to 1000+
     * Monitor failure points
   - Expected outcome: Identify maximum capacity

3. ENDURANCE TESTING
   - Objective: Detect memory leaks and degradation over time
   - Duration: 24-48 hours of continuous load
   - Monitoring: Memory, CPU, disk usage patterns

4. SPIKE TESTING
   - Objective: Test sudden load increases
   - Scenario: Jump from 50 to 500 users instantly
   - Verify: System recovery after spike

5. VOLUME TESTING
   - Objective: Test with large datasets
   - Scenarios:
     * Database with 1M+ records
     * Large file uploads/downloads
     * Batch processing operations

### 1.3 Performance Metrics

Response Time Metrics:
  - Average Response Time (Target: < 2 seconds)
  - 95th Percentile (Target: < 5 seconds)
  - 99th Percentile (Target: < 10 seconds)
  - Min/Max Response Time

Throughput Metrics:
  - Requests Per Second (RPS) - Target: > 100 RPS
  - Transactions Per Second (TPS)
  - Data Throughput (KB/s)

Resource Utilization:
  - CPU Usage (Target: < 80%)
  - Memory Usage (Target: < 75%)
  - Disk I/O (Read/Write operations)
  - Network Bandwidth

Reliability Metrics:
  - Error Rate (Target: < 1%)
  - Success Rate (Target: > 99%)
  - Availability (Target: > 99.5%)
  - Time to First Byte (TTFB)

### 1.4 Performance Testing Prerequisites

Technical Requirements:
  ✓ Production-like test environment
  ✓ Realistic test data (minimum 1M records)
  ✓ Monitoring infrastructure (Prometheus, Grafana)
  ✓ Load generation tools installed

### 1.5 Performance Test Execution Plan

Phase 1: Baseline Testing (Week 1)
  - Establish current performance metrics

  - Identify quick wins for optimization

Phase 2: Load & Stress Testing (Week 2)
  - Execute load test scenarios

## PART 2: FUNCTIONAL TESTING

### 2.1 Overview
Functional testing verifies that the application behaves as expected according 
to functional requirements and specifications.

### 2.2 Types of Functional Testing

1. UNIT TESTING
   - Objective: Test individual methods/functions
   - Scope: Single unit of code
   - Framework: JUnit 4/5, TestNG
   - Example: Test Calculator.add() method
   - Coverage Target: > 80%

2. INTEGRATION TESTING
   - Objective: Test interactions between modules
   - Scope: Multiple components working together
   - Focus: Data flow between components
   - Example: Calculator + Database + API layer

3. SYSTEM TESTING
   - Objective: Test complete system as a whole
   - Scope: Entire application end-to-end
   - Environment: Test environment matching production
   - Validates: All functional requirements

4. REGRESSION TESTING
   - Objective: Ensure new changes don't break existing features
   - Trigger: After each code change
   - Scope: Automated test suite
   - Tools: Selenium, JUnit, TestNG

5. USER ACCEPTANCE TESTING (UAT)
   - Objective: Verify system meets business requirements
   - Participants: Business users, stakeholders
   - Scenarios: Real-world use cases
   - Duration: Before production deployment

### 2.3 Functional Testing Tools

Java Testing Frameworks:
  - JUnit 4/5 (Unit testing)
  - TestNG (Advanced unit testing)
  - Mockito (Mocking framework)
  - PowerMock (Static method mocking)

Web/API Testing:
  - Selenium (UI automation)
  - RestAssured (REST API testing)
  - Cucumber (BDD testing)

### 2.4 Functional Testing Prerequisites

Development Environment:

  ✓ IDE: IntelliJ IDEA or Eclipse

Testing Frameworks & Libraries:

  ✓ TestNG 7.x
  ✓ Mockito 3.x
  ✓ RestAssured 4.x
  ✓ Selenium 3.x (for UI testing)

Test Data Requirements:

Documentation:
  ✓ Functional requirements documented
  ✓ Test cases written and reviewed
  ✓ API specifications documented

  ✓ Known issues documented

### 2.6 Functional Test Example (JUnit)

```java
import org.junit.jupiter.api.Test;
import static org.junit.jupiter.api.Assertions.*;

public class CalculatorTest {
    
    private Calculator calculator = new Calculator();
    
    @Test
    public void testAddition() {
        int result = calculator.add(5, 3);
        assertEquals(8, result, "5 + 3 should equal 8");
    }
    
    @Test
    public void testSubtraction() {
        int result = calculator.subtract(5, 3);
        assertEquals(2, result, "5 - 3 should equal 2");
    }
    
    @Test
    public void testDivisionByZero() {
        assertThrows(ArithmeticException.class, () -> {
            calculator.divide(5, 0);
        });
    }
}
```

### 2.9 Functional Testing Best Practices
  - Write tests before or with code (TDD)
  - Use meaningful test names
  - Keep tests independent and isolated
  - Mock external dependencies
  - Use test fixtures for setup/teardown
  - Maintain test data carefully
  - Run tests frequently (CI/CD)
  - Document test results
  - Track defects properly

## PART 4: TOOLS & COMMANDS

### Performance Testing with JMeter

Installation:
  1. Download JMeter from https://jmeter.apache.org/
  2. Extract to local directory
  3. Run: jmeter.bat (Windows)

Basic Test Plan:
  1. Create Thread Group (number of users)
  2. Add HTTP Sampler (target URL)
  3. Add Listeners (View Results Tree, Aggregate Report)
  4. Configure Ramp-up and Duration
  5. Run test and analyze results

### Functional Testing with JUnit

Run tests via Maven:
  mvn clean test
  mvn test -Dtest=CalculatorTest
  mvn test -Dtest=CalculatorTest#testAddition

Run tests via Gradle:
  gradle test
  gradle test --tests CalculatorTest
  gradle test --tests CalculatorTest.testAddition

### Code Coverage with JaCoCo

Generate coverage report:
  mvn clean test jacoco:report
  
View report:
  target/site/jacoco/index.html
